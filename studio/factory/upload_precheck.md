# 업로드 전·후 사람 검수 (G1/G2/F3)

업로드는 사람이 실행한다. 이 문서는 업로드·삭제 권한을 자동화하지 않는다.

## 전달 전 (F3)

- [ ] 최종 영상과 입력의 input_sha256가 현재 qa.json과 일치한다.
- [ ] 모든 [자동] 게이트 PASS, 모든 [자동+서명] 항목 CTO_SIGNED다. 자동 FAIL은 서명으로 해제할 수 없다.
- [ ] D2의 모든 샷 MATCH 및 B4의 모든 읽힌 명칭이 CTO 서명에 있다. 제작 측 MATCH는 인정하지 않는다.
- [ ] CTO 서명 후 CEO가 최종 인코딩과 근거 시트를 직접 시각 검수하여 PASS를 기록했다.
- [ ] CEO 시각 도구가 막혀 있으면 blocker로 보고하고 원일에게 전달하지 않는다.
- [ ] 위 조건 충족 후에만 원일에게 전달한다. qa.json의 '실시간 재생 미검수' 한계를 함께 전달한다.

## 업로드 직전 (G1/G2)

- [ ] YouTube Studio에서 **KST 오늘 00:00–24:00**의 업로드 수를 직접 센다. 교체 업로드도 포함한다. 공개·예약·비공개를 모두 확인한다.
- [ ] 오늘 업로드가 **1개 이상이면 즉시 중단한다**. 교체라는 이유로 두 번째 업로드를 하지 않는다.
- [ ] 업로드할 번호·qid·video_id·상태·날짜를 로컬 `upload/ledger.json`과 Studio 목록에서 대조한다.
- [ ] 교체로 생긴 비공개 잔존본은 **0개**여야 한다. 무의미한 비공개본이 있으면 사람이 확인하여 정리하고 원장도 맞춘다.
- [ ] 번호 중복·원장 불일치·잔존본이 있으면 업로드를 중단한다.
- [ ] 영상·커버·제목·설명·공개 설정·예약 시각을 확인한 뒤 사람이 업로드한다.

## 업로드 직후 (G1/G2)

- [ ] Studio에서 실제 video_id·번호·qid·공개/예약 상태·KST 날짜를 확인하고 원장에 반영한다.
- [ ] Studio 목록과 원장의 항목·상태가 일치하는지 다시 대조한다.
- [ ] 교체된 이전 비공개 잔존본이 **0개**인지 재확인한다. 무의미한 영상이 남지 않아야 한다.
- [ ] 오늘 업로드 수(교체 포함)가 **1개 이하**인지 확인하고 Studio 확인 시각·검수자·결과를 기록한다.
- [ ] 오류가 있으면 추가 업로드로 고치지 말고 중단·보고한다. 다음 조치는 사람이 결정한다.
