# 제작 담당 코딩 에이전트 지시서

사용자 조건은 확정됐다. 레퍼런스 Tōdai의 화면풍을 기준으로, 글로벌 영어·9:16·30~45초·가벼운 인물 상황극을 만든다. 모든 추가 지출은 0, 사용자는 단계별 컨펌만 한다. 물체 콘텐츠로 제한하지 않는다. 설치·모델링·리깅·디버깅을 사용자에게 지시하지 말고 담당 에이전트가 수행한다. 구매·계정 생성·공개 업로드를 하지 않는다.

## 이번 릴리스의 실제 상태

저장소 bootstrap과 Node/브라우저 렌더 코드가 작성돼 있지만, 작성 환경에서 공개 소스 다운로드가 차단됐다. **원본 및 신작 WebGL 렌더는 미실행**이다. VERIFY.md의 테스트 통과를 시각 품질 통과로 인용하지 않는다. 이전 대화의 "완성" 표현을 근거로 생략하지 않는다.

## 가장 먼저 할 일

1. README의 의존성을 로컬에 설치하고 `npm run setup`으로 pinned source를 받는다. 필요한 원본 경로/4개 git blob 해시가 다르면 멈춰 원인을 확인한다. 원본을 조용히 latest로 바꾸지 않는다.
2. `npm run reference`를 실행한다. 원본 제작자 결과가 재현되는지 확인한다. 이 출력을 새 작품이나 본인이 만든 성공 샘플이라고 표시하지 않는다.
3. `npm run style`로 **새 캐릭터와 새 장면**을 실제로 출력한다. 원본과 같은 크기로 나란히 본다. 캐릭터·배경·조명·외곽선·움직임이 부족하면 그 부분을 수정한다. blur/bloom/grain으로 모델/연기 부족을 숨기지 않는다.
4. 사용자에게 6초 영상과 핵심 대표 화면만 보여주고 큰 수정사항을 묻는다. 레퍼런스급이라고 먼저 선언하지 않는다. 문서나 테스트 목록으로 대신하지 않는다.

## 절대로 하지 말 것

- 렌더가 안 될 때 스토리보드 SVG를 MP4로 묶어서 실제 3D 결과처럼 전달하지 말 것.
- 원본 영상 재출력을 우리 신작이라고 말하지 말 것.
- 미검증 클래스/API가 동작한다고 가정하지 말 것. 실제 브라우저 shader 오류를 확인할 것.
- 샘플이 좋지 않은데 계속해서 생산관리 플랫폼을 확장하지 말 것.
- 사용자에게 이미 답한 비용·레퍼런스·역할을 재질문하지 말 것.
- 사람 검수용 작은 출력에서 캐릭터, 동작, 재질과 주요 효과를 삭제하지 말 것.
- 서버/분산 큐/범용 행동 언어/동등한 Blender 렌더 엔진을 추가하지 말 것.

## 장면 제작 방식

현재 예제는 고정된 인물/세트만 지원하는 **초기 장면 코드**다. 품질 상한으로 받아들이지 말고 실제 대표 샷의 결과를 보고 다듬는다. 임의 리그를 지원한다고 선언하지 않는다. 기존 분절형 모델에서 더 섬세한 스킨 리그로 변경하려면 toon/outline 모두에 변형 지원을 넣고 실제 변형 프레임을 확인해야 한다.

- 시나리오: 화면으로 보이는 동작으로 적는다. 모든 컷의 존재 이유를 적되 별도 문서를 늘리지 않는다.
- 보드: 실제 패널. 필요하면 기존 3D 세트의 키포즈에서 뽑는다.
- 목소리: 로컬 무료 Kokoro 또는 사용 허가된 녹음. 임시 기계음성을 최종처럼 자동 대체하지 않는다. voice.py가 막히면 설치/발음/길이를 담당 에이전트가 고친다.
- 캐릭터: 같은 인물은 같은 자산과 버전을 쓴다. 인물 수나 신체가 단순해도 눈/몸/손의 행동은 정교하게 만든다.
- 샷: 절대 시간(local frame)의 pure pose 함수. seed 고정. 방문 순서가 결과를 바꾸면 고친다.
- 접촉: 위치 anchor와 접촉/해제 구간이 실제로 맞는지 본다. 일반화된 자동 물리로 가정하지 않는다.
- 미술: 색 대본, 대표 빛, clean cel / painted background 마스크를 유지한다.
- 출력: 원본 360×640로 연기를 검토하고 필요한 최종 크기만 선택적으로 확인한다.

## 리뷰 전달

"이번에는 무엇을 결정해야 하는가"를 최대 3문장으로 알려준다. 타임코드+변경 요청만 받는다. 기존 방향 안에서 가능한 작은 기술·연출 문제는 담당자가 해결한다. 같은 자산/룩을 다음 편마다 다시 승인받지 않는다.

도구가 반환한 경로만 믿지 말고 **실제 파일이 현재 파일시스템에 존재하는지 확인**한다. 사용자에게 전달할 MP4는 실제 접근 가능한 첨부로 복사한다. 내부 작업 경로나 없는 파일을 링크하지 않는다. 영상이 열리는지 파일 크기·ffprobe·디코드를 검사한다. 사용자에게 ZIP을 풀어 영상을 찾으라고 떠넘기지 않는다.

## 끝까지 완주한 뒤

`npm run review` → 실제 음성·효과 연결 → 전편 검토 → 수정된 샷만 재렌더 → `npm run final` → `npm run deliver`.

실제 파일을 연속 시청·청취한다. 수치 검사로 표정/접촉/재미를 통과시키지 않는다. SRT는 별도 파일이며 현재 자동 burn-in은 구현돼 있지 않다. 필요한 경우 편집 단계에서만 처리하고 3D를 다시 렌더하지 않는다.

다음 편은 같은 시작 상황을 반복하지 말고 목적/장애/전환/보상이 다른 이야기로 만든다. 그때 재사용된 자산/동작과 새로 보정한 작업을 구분해 기록한다. 하루 한 편/완전 무인/레퍼런스 동급은 실제 완성 영상과 후속 제작 기록 전에는 주장하지 않는다.
